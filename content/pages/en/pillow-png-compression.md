You lower `quality` to make a PNG smaller with Pillow, but the file size does not change. That can be confusing if you expect it to work like JPEG.

In the comparison, PNG `quality=10` and `quality=90` produced files identical to the default—not just the same size, but the same contents. For PNG size, the useful controls were `compress_level` and `optimize`.

I had Codex run the comparison script in my blog’s working environment on September 15, 2026. Here are the results and code you can try on your own machine.

## Which settings can reduce PNG size?

If file size is your priority, try `optimize=True` and save to a different file so the original stays intact:

```python
from PIL import Image

with Image.open("input.png") as image:
    image.save("output-optimized.png", format="PNG", optimize=True)
```

To compare compression levels without `optimize`, use `compress_level`:

```python
with Image.open("input.png") as image:
    image.save("output-level1.png", format="PNG", compress_level=1)
    image.save("output-level6.png", format="PNG", compress_level=6)
    image.save("output-level9.png", format="PNG", compress_level=9)
```

`compress_level` ranges from 0 to 9, and the default is 6. With `optimize=True`, Pillow uses compression level 9, so a separately supplied level is not used. See [Pillow’s PNG saving options](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#png). The key point is not to treat JPEG’s `quality` option as a PNG image-quality control.

## Results on the same images

The environment was Windows, Python 3.10.1, Pillow 12.3.0, and zlib 1.2.11. Each setting had one warm-up save, then five timed saves; the table shows their median. Times exclude image loading, resizing, and decoding.

The first input was a 640 × 480 RGB image generated by a script. It contains areas with color changes and square boundaries, and the same code creates the same input each time.

| Save settings | File size | Save time |
| --- | ---: | ---: |
| Default | 2,639 bytes | 3.70 ms |
| `quality=10` | 2,639 bytes | 3.76 ms |
| `quality=90` | 2,639 bytes | 3.98 ms |
| `compress_level=0` | 922,446 bytes | 4.63 ms |
| `compress_level=1` | 11,293 bytes | 4.17 ms |
| `compress_level=9` | 2,199 bytes | 6.42 ms |
| `optimize=True`, level 1 | 2,199 bytes | 6.95 ms |
| `optimize=True`, level 9 | 2,199 bytes | 6.81 ms |

All three `quality` results had identical file contents. The two `optimize=True` results also matched: optimization uses level 9, so adding level 1 did not make the compression lighter.

The second input was a keyboard photo from the [CHUWI CoreBook X unboxing post](/chuwi-corebook-x-review.html). The test converted the JPEG to RGB and resized it to fit within 640 × 480; the resulting image was 562 × 480 pixels.

| Save settings for the photo-derived image | File size | Save time |
| --- | ---: | ---: |
| Default | 316,511 bytes | 20.43 ms |
| `quality=10` | 316,511 bytes | 19.99 ms |
| `quality=90` | 316,511 bytes | 19.81 ms |
| `compress_level=0` | 810,092 bytes | 5.12 ms |
| `compress_level=1` | 457,345 bytes | 7.37 ms |
| `compress_level=9` | 310,636 bytes | 114.81 ms |
| `optimize=True`, level 1 | 310,398 bytes | 115.47 ms |
| `optimize=True`, level 9 | 310,398 bytes | 113.64 ms |

Again, the `quality` values matched each other, as did the two `optimize=True` results. On this photo, `optimize=True` reduced the default size by only about 1.9%, while taking roughly 5.6 times longer. The impact can vary by image.

Pillow’s [PNG save-time discussion in issue 5986](https://github.com/python-pillow/Pillow/issues/5986) may also be useful if compression is taking longer than expected.

## Did the image quality change?

The script reopened each PNG and compared its dimensions, mode, and every pixel with the input. All 16 outputs matched exactly. These lossless compression settings stored the same pixels differently; they did not lower image quality.

This comparison did not cover transparent PNGs, palette images, 16-bit images, or APNG. The photo example converts to RGB, so do not use that exact conversion when you need to preserve transparency.

## Reproduce the comparison on your own files

The full [comparison script is on GitHub](https://github.com/ligfil-8110/ligfil-8110.github.io/blob/main/scripts/compare_png_options.py). It works with Python 3.10 or later; install Pillow in a virtual environment if needed.

```shell
python -m pip install Pillow==12.3.0
python scripts/compare_png_options.py
```

With no image argument, it uses the generated test image. It saves and decodes data in memory, without writing image files or logs to disk. To compare your own photo:

```shell
python scripts/compare_png_options.py your-photo.jpg --repeats 5
```

The input is opened read-only; orientation correction, RGB conversion, and resizing happen in memory. Results depend on the input, and timings can vary with the computer and its workload. Compare the file size and pixels, then choose the setting that fits your use case.

For PNGs, first check whether the image dimensions are larger than you need. Then compare compression settings. `optimize=True` is not automatically worthwhile: on the photo in this test, it took much longer for a small reduction in size.
